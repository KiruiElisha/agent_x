WhatsApp API

Send and receive WhatsApp from your own app.

This service keeps the phone session. Your app sends and receives over HTTP. You do not install anything beside the app. Anything that already uses an instance id and an access token only needs this site as its API address. One client can link more than one phone. Each phone is its own instance.

API documentation

Send these requests to . Public signup and login do not need a token. Every other call sends Authorization: Bearer with either the client access token or the operator token.

Authentication

A client token can only open its own numbers. The operator token can open every number, including the service number whose instance id is service.

Create a client

POST/api/signup

No token. The response includes the access token and instance id once.

curl -s -X POST /api/signup \
  -H 'Content-Type: application/json' \
  -d '{"id":"acme","email":"you@company.com"}'
POST/api/login
curl -s -X POST /api/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@company.com"}'

Link a phone

POST/api/sessions/INSTANCE/start
curl -s -X POST /api/sessions/INSTANCE/start \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"webhook_url":"https://erp.example.com/hook","webhook_secret":"replace-me"}'
GET/api/sessions/INSTANCE/qr

Returns the QR image as a data URL. Use the pair call when the phone should type a code instead.

curl -s -X POST /api/sessions/INSTANCE/pair \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"phone":"254712345678"}'

Send

POST/api/sessions/INSTANCE/send
curl -s -X POST /api/sessions/INSTANCE/send \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"to":"254712345678","text":"Hello"}'

A picture uses media with a url and an optional caption. An unpaid client returns 402 when a subscription is required. A disabled client returns 403.

POST/send

Same request with the token and instance id in the body. The path is on this site, not under /api. Call it again to link another phone. The earlier numbers stay connected.

curl -s -X POST /send \
  -H 'Content-Type: application/json' \
  -d '{"access_token":"TOKEN","instance_id":"INSTANCE","number":"254712345678","message":"Hello"}'

Subscriptions

POST/api/billing/pay

Client token. M-Pesa returns invoice_id. A card plan returns setup_url.

curl -s -X POST /api/billing/pay \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"phone":"254712345678"}'
GET/api/billing/status

Tells this client whether the subscription is active, the price, and how payment is collected.
